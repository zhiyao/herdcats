Power optimization: bounded behavioral coverage

Scope: C1 hidden terminal work and C2 scene-aware recovery. These checks
exercise executable interfaces; none inspect implementation source strings.

Evidence levels
- App-driven: XCTest UI navigation and foreground restoration in the existing
  screenshot-fixture simulator. This exercises SwiftUI lifecycle/navigation,
  but the fixture bypasses SSH, Live-shell setup, and remote input delivery.
- Component integration: production polling/Live runners, PaneSessionState,
  ANSI parsing, input coordinator, session retirement, and AppModel recovery
  with controlled clocks/transports. Connected cancellation tests use a
  test-owned Citadel SSH server bound to 127.0.0.1 on an ephemeral port.
  Its exec delegate rejects persistent shell setup; it is not a Herdr/Pi lab.

Scenario coverage and limits
1. Timeline stops terminal polling/parsing/Live acquisition:
   hiddenTimelineNeverReadsParsesOrSleepsInTerminalPollingRunner and
   hiddenTimelineNeverAcquiresLiveSessionOrShells assert zero work at the
   production runner boundaries. The mode-switch test executes ANSI parsing.
   No app-driven backend command counters or power measurements are available.
2. Terminal entry is fresh with auto-refresh disabled; Timeline retires shells:
   modeSwitchingStartsFreshTerminalWorkOnEntryAndRetiresShellsOnTimelineReturn
   checks successive snapshots/revisions and both shell close side effects.
   The UI mode-switch check proves navigation/rendering only, not remote input.
3. Leave Terminal during acquisition/Compose:
   cancellationOrTimelineSwitchMidBeginOrReadRetiresTokenWithoutInstalling,
   connected cancellation tests, and
   leavingTerminalDuringComposeRetiresConnectedAcquisition cover stale-token
   rejection and retirement, including a rejected send using the late token.
   Compose is represented by holding the production input lane, not a remote
   mutation. Persistent shell success and real Herdr input replay are not
   driven by the loopback exec fixture.
4. Background during recovery/resync; foreground restores recovery:
   pendingAutoReconnectCancelsWhenSceneBecomesInactiveAndLossWhileInactiveNeverDials
   checks pending timer cancellation and foreground dial eligibility.
   The queued-Compose check also backgrounds while Live resync is blocked.
   The UI foreground test exercises app lifecycle with static Timeline data;
   it does not interrupt or restore an authenticated remote session.
5. Outage and short-lived reconnect backoff:
   repeatedReconnectFailuresBackOffAndResetOnlyAfterStableSuccess covers dial
   failures. scheduledRetriesDialAndBackOffAcrossShortLivedSuccesses releases
   each actual AppModel timer, observes its dial, drops short-lived successes,
   reaches the cap, then verifies reset after 30 seconds of injected stable time.
   This is deterministic timing proof, not wall-clock SSH outage evidence.
6. Retry bypasses backoff; host-key/disconnect protection:
   explicitManualRetryDialsImmediatelyEvenDuringLongOutageBackoff and
   hostKeyChallengeBlocksAutomaticReconnectUntilApprovedAndUserDisconnectResetsSession
   exercise recovery entry points and state. UI tapping Retry against a real
   host-key challenge remains untested.
